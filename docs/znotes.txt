# Hey Grok

We need to implement a function that evaluates student placement data and categorizes each student's admitted status into one of two destination tables: 
- Admitted Table (Direct Admission) or Redirected Admission Table.

The system must dynamically resolve inconsistent naming conventions between two data sources: the Client List and data/school-directory.json.

# 1. Target Output Tables & Logic
Admitted Table (Direct Admission): The student was admitted into their exact School of Choice.
Redirected Admission Table (Scenario A): The student was admitted into a different school, but it is located in the same Local Government Area (LGA) as their original School of Choice.
Redirected Admission Table (Scenario B): The student was admitted into a different school located in a different LGA than their School of Choice.

# 2. The Matching Challenge
School names do not match exactly across datasets due to abbreviations and formatting differences.
Example 1: Client List says COMM JNR GRAMM SCH IPAJA → Directory says COMM. JNR GRAM, IPAJA (LGA: ALIMOSHO).
Example 2: Client List says AJAO EST JNR GRAMM SCH → Directory says AJAO ESTATE SEC. SCH (LGA: OSHODI-ISOLO).

# 3. Proposed Implementation Strategy

To solve this cleanly without modifying the raw source files, implement the following multi-step matching pipeline:
Step 1: Student Identity Verification (Exact Match)
Filter and isolate the student's records in the main dataset using an exact match on Name and Sex.
Step 2: Text Normalization (Preprocessing)
Before comparing school names, pass strings through a cleaning function that:
- Converts all text to lowercase.
- Removes punctuation (dots, commas, hyphens).
- Standardizes common abbreviations (e.g., replace jnr with junior, sch with school, gramm or gram with grammar, est with estate). I previously did this in normalize-school-name.ts but somehow you cleared it..

Step 3: Fuzzy String Matching (The "Smart" Boundary Search)
Use a fuzzy matching library (like RapidFuzz or PolyFuzz) to calculate similarity scores between the Client List's School of Choice and the names listed in school-directory.json.
- Set a high confidence threshold (e.g., >85%).
- If a match is found within the threshold, extract that school's official LGA from the directory.

Step 4: Admission Classification
Compare the student's Actually Admitted School against the resolved School of Choice:
If Normalized(Actual School) == Normalized(School of Choice) → Admitted Table.
If they differ, look up the LGA of the Actual School. 
If Actual LGA == Choice LGA → Redirected Table (Same LGA).
If LGAs differ → Redirected Table (Outside LGA).
